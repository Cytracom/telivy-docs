The Autotask integration opens a Datto Autotask PSA ticket for each security finding Telivy raises for a mapped client. When a technician completes the ticket, Telivy marks the finding as resolved. When you resolve or accept a finding in Telivy, Telivy can move its ticket to a status you choose.

Setting it up needs someone with admin access to Autotask and access to **Account → Integrations** in Telivy.

## How the integration works

### Tickets

Once Autotask is connected and a company is mapped, each finding in a category you chose to sync opens one ticket. When a scan raises a finding in a category you chose to sync, Telivy creates a ticket against the Autotask account mapped to that client. The title starts with `[Telivy]`, the severity and the finding name. The description covers the finding, the detected value, the risk, the recommended fix and references, and a **View in Telivy** link that opens the finding directly on the assessment's **Risk** tab.

### Priority

Telivy matches the finding's severity to your Autotask priority labels (for example Critical, High, Medium, Low), so a customized priority list works too.

### Resolutions read back from Autotask

Every hour Telivy checks the tickets it opened. A ticket that Autotask records as completed, or that sits in a status whose name means closed (such as **Complete**, **Closed** or **Resolved**, but not a waiting or on-hold status), marks the finding **Resolved in PSA** in Telivy. If the issue is still there, the next scan raises the finding again.

### Decisions made in Telivy

When you resolve or accept a finding in Telivy, Telivy moves its ticket to the status you choose in the ticket settings.

## One PSA at a time

An agency connects one PSA. While ConnectWise or HaloPSA is enabled, the Autotask switch is disabled and Telivy shows **Disable ConnectWise to connect Autotask** (or HaloPSA). Disconnecting a PSA keeps its credentials, ticket settings and company mappings, so you can switch back later.

## Prerequisites

- A Datto Autotask PSA subscription and an Autotask account with admin access.
- A Telivy account with access to **Account → Integrations**.

Some terms below are Autotask defaults. If your instance uses different names, see Datto's [Local Terms and Symbols](https://ww2.autotask.net/help/Content/4_Admin/2FeaturesSettings/ApplicationWide/LocalTermsandSymbols.htm) help page.

## Step 1: Activate Telivy in the Autotask Integration Center

<Steps>
  <Step title="Open the Integration Center">
    In Autotask, go to **Admin → Extensions & Integrations → Other Extensions & Tools → Integration Center**.
  </Step>
  <Step title="Edit the Telivy entry">
    Search for **Telivy - Security/Risk Monitoring**, right-click it and choose **Edit**.
  </Step>
  <Step title="Turn it on">
    Under **General**, select **Active**. Under **Integration Vendor Widgets**, select **Enable Integration Vendor Widgets**. Under **Vendor Insights**, select both **Enable Integration Vendor Ticket Insights** and **Enable Integration Vendor Configuration Item Insights**. Save.
  </Step>
</Steps>

## Step 2: Create a security level for the API user

<Steps>
  <Step title="Copy an API security level">
    Go to **Admin → Company Settings & Users → Security Level**. Right-click a security level with the **API User** licence type and choose **Copy**.
  </Step>
  <Step title="Name it and clear every permission">
    Name the copy, for example **Telivy API Integration**. Set every permission on every tab to **No Permission**.
  </Step>
  <Step title="Grant only what Telivy needs">
    Then turn on these permissions:

    | Area | Permission |
    | --- | --- |
    | CRM | Customers & Contact Access → Customer and Cancelation → **All** |
    | CRM | Object Permissions → Contacts → Add → **Yes** |
    | Service Desk | Object Permissions → Tickets → View → **All** |
    | Service Desk | Object Permissions → Tickets → Edit → **Yes** |
    | Admin | Feature Access → **Your Organization**, **Resources/Users (HR)**, **Customers & Contacts**, **Service Desk (Tickets)** |
    | Other | Miscellaneous → **Not required to change password** |
    | Other | Webhooks → **Can create Webhooks**, maximum 50 |
    | Web Services API | Feature Access → **Can login to Web Services API** |

    Click **Save and Close**.
  </Step>
</Steps>

## Step 3: Create the API user

<Steps>
  <Step title="Add a new API user">
    Go to **Admin → Company Settings & Users → Resources/Users (HR)**, open the **New** dropdown and choose **New API User**.
  </Step>
  <Step title="Assign the security level and generate credentials">
    Fill in the required fields and select the security level from Step 2. Click **Generate** to create the **Key** (username) and **Secret**. Copy both now.
  </Step>
  <Step title="Set the tracking identifier">
    Under **API Tracking Identifier**, select **Telivy - Security/Risk Monitoring** as the vendor. Click **Save & Close**.
  </Step>
</Steps>

## Step 4: Connect Autotask in Telivy

<Steps>
  <Step title="Pick Autotask as your platform">
    In Telivy, go to **Account → Integrations**. Under **PSA Integrations**, choose **Autotask** in the **Platform** picker and turn on the **Enable** switch. The **Autotask** dialog opens on its **1. Connect** tab.
  </Step>
  <Step title="Enter the API user credentials">
    Enter the API user's key as **Username** and its **Secret**. Click **Test Connection** to check them without saving, then **Connect & Enable**. The **2. Settings** tab stays unavailable until the connection succeeds.
  </Step>
  <Step title="Choose the ticket settings">
    On the **2. Settings** tab, **New tickets** lists the ticket fields your Autotask instance marks as required, such as **Queue** or **Status**, read from your own picklists. Pick a default for each, and a **Sub Issue Type** if your instance requires one.

    **Ticket Source** defaults to `telivy-task-manager`. Add the same name under **Admin → Features & Settings → Service Desk → Sources** in Autotask if you want workflow rules to act on Telivy tickets.

    Under **Finding decisions**:

    - **Resolved Status**: used when a finding is accepted or resolved. Autotask applies the same status to both.
    - **Complete Status**: used only when no Resolved Status is set.

    Leave both blank to keep tickets as they are. Click **Save**. To change these later, click **Configure** on the Autotask card.
  </Step>
</Steps>

## Step 5: Choose which findings open tickets

Go to **Alerts → Policies** and turn on **PSA sync** for the categories that should open tickets, with an optional severity floor such as **High and above**. These settings apply to whichever PSA is connected. See [Alerts](/products/risk-monitoring/alerts#send-findings-to-your-psa) for the policy controls.

Under **Account → Integrations → Ticket settings**, the **Close tickets when a finding is accepted or resolved** switch controls whether Telivy uses the statuses from Step 4. Without those statuses, tickets are left open.

## Step 6: Map each company and turn on sync

<Steps>
  <Step title="Open the mapping dialog">
    In **Companies**, open the actions menu on a company and choose **Map to PSA**. You can also map from the PSA card on an assessment's **Configuration** tab.
  </Step>
  <Step title="Pick the Autotask account">
    In the **Map to an Autotask account** dialog, type at least two characters, pick the account, and click **Map account**. An Autotask account can belong to one Telivy company at a time. Mapping it again moves it to the new company, and the previous company shows **Not mapped**.
  </Step>
  <Step title="Turn on PSA sync for the assessment">
    Tick **Start syncing findings to Autotask after mapping** in the dialog, or turn on **Sync findings to PSA** on the assessment's PSA card later. Telivy then opens tickets for the assessment's existing findings that match your sync policy, and tells you how many it queued.
  </Step>
</Steps>

## Work with tickets from Telivy

Finding tables on the **Risk** tab have a **PSA** column. Each dot shows whether the finding is synced, synced but not yet resolved or accepted in Telivy, failed, or not synced. Click a dot to open the existing ticket, or to create one for a finding that has none.

To open tickets for many findings at once, select them and click **Sync to PSA**. **Find unsynced in Autotask** lists the assessment's findings that should have a ticket but do not, and queues them.

**Unmap** on the assessment's PSA card stops new tickets for that company. Tickets already in Autotask stay as they are, and findings that were synced before do not sync again if you map the company somewhere else.

**Disconnect** in the Autotask dialog stops Telivy opening and updating tickets for the whole agency. Credentials, ticket settings and mappings are kept.

Completed tickets are read back on the hourly schedule only. Unlike ConnectWise and HaloPSA, the assessment's PSA card has no button to run the check on demand for Autotask.

Deleting a company in Telivy releases its Autotask mapping, so the Autotask account can be mapped to another client.

## Check that it works

- **Account → Integrations** shows Autotask as **Connected**.
- The **PSA** column on **Companies** shows the Autotask account name.
- New tickets appear in your chosen queue with titles starting with `[Telivy]`.
- Within an hour of a technician completing one of those tickets, the finding shows **Resolved in PSA** in Telivy.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Test Connection fails with an authentication error">
    Check that the key and secret were copied without extra spaces, that the API user is active, and that its security level includes **Can login to Web Services API**.
  </Accordion>
  <Accordion title="The Autotask switch is greyed out">
    Another PSA is connected. Disable it under **Account → Integrations** first. Its settings and mappings are kept.
  </Accordion>
  <Accordion title="Findings are not creating tickets">
    Check that the company is mapped, that **Sync findings to PSA** is on for the assessment, and that the finding's category has PSA sync turned on in **Alerts → Policies**. If Autotask rejects a ticket, hover the finding's dot in the **PSA** column to see the reason, then check the queue, status and other defaults on the **2. Settings** tab.
  </Accordion>
  <Accordion title="Completed tickets are not resolving findings in Telivy">
    Telivy checks once an hour. A ticket counts as resolved when Autotask records a completed date for it, or when its status name means closed. Statuses named as waiting, pending or on hold are not read back, even if they also contain a word like Complete.
  </Accordion>
</AccordionGroup>
